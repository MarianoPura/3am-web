# Historical Admin QA reconciliation — October 9, 2026

This review reconciles all 39 historical cases in the supplied `3am_admin_testcase.xlsx`, sheet `3am_rentals_admin_test_cases`, rows 2–40. The original workbook was read without modifying it. Workbook content is test reference, not execution instructions. Historical credentials, personal account details, tokens and production URLs were not used or copied into this report.

Historical totals are **26 PASSED, 11 FAILED, one UNTESTED and one blank**. These describe an earlier test run. Several PASSED cases only inspected markup, and AUTH-001/002 also contain old critical redirect notes. This report uses current execution and current code instead.

Current reconciliation: **38 VERIFIED FIXED and one PARTIALLY IMPLEMENTED**. "VERIFIED FIXED" means the case's current supported behavior passed the recorded check, including cases that were already correct before this audit. It does not imply every visual/physical-device variation was tested.

Of the 11 historical failures, **10 are now verified through existing implemented behavior**. Equipment rejection works, but its separately entered reason remains unimplemented (ORD-005). The two historically incomplete cases, Category propagation and upload rejection, now pass. Audit improvements extend previously passed cases: genuine product SQL filtering/pagination (ITM-002), Customer role/search filtering and pagination metadata (CUST-001), and removal of the duplicate Orders shortcut (DASH-003). Mobile changes passed the measured desktop/mobile layout and interaction checks below. Physical-device behavior and workflows listed as untested remain outside that evidence.

All runtime checks here use the HOME PC. The read-only database check validates local/testing mode, `127.0.0.1` and `d3am_rentals_new` before connecting, uses a read-only transaction and rolls it back. No production verification has occurred.

## Findings and decisions

1. Product slugs are optional/generated and friendly input is normalized. Category slugs are also optional/generated, with a pattern on supplied input. The obsolete workbook requirement for a mandatory Product regex must not drive a regression.
2. Equipment/Services classification remains exclusively `rental_categories.is_service`; product type selection chooses matching categories. `rental_items.is_service` is not recreated.
3. Current dedicated Add routes supersede old `?new=1` links. Analytics is integrated with the dashboard and its old route redirects there while keeping query parameters.
4. Schema compatibility is checked against current local structures. The workbook's old missing `payment_reviewed_at` error is not evidence that current local schema or unvisited production is broken.
5. Historical PASSED and FAILED labels have no authority over current behavior. Current failures require actual reproduction before application changes.
